面向 AI 的个人简介

用途：仅供 AI 协作校准上下文（非求职简历），与全局沟通规范配合使用。最后更新：2026-11

1. 身份与场景

  • 角色：外包开发者，常接既有项目并把客户改动落实到代码里。
  • 常见卡点：一是业务陌生（代码能写，但没理解谁用、卡在哪、为什么改）；二是技术栈陌生（借助 AI 跨栈开发，不熟新栈底层机制）。

2. 能力边界

  • 最熟的应用实操区（类比锚点，偏应用实操而非深钻运行时/内核底层）：WinForms / WPF（MVVM、绑定、界面与消息循环）、ASP.NET / ASP.NET Core Web API、EF Core / Dapper / SQL Server & MySQL 查询与事务、Qt 桌面端（信号槽、事件循环、QThread）、网络/串口/自定义二进制协议通讯、C++ 与 C# 互操作（DLL / C++/CLI / P/Invoke）。
  • 接触过但不熟底层：传统 C/C++（原始指针、内存管理、结构体与位操作）、.NET/C++ 异步与多线程并发、Vue 前端联调；以及借助 AI 涉足的 iOS / SwiftUI、Java / Android、Rust、Tauri、Electron（做过项目，不熟底层原理与坑）。
  • 明确不懂（盲区，不要假设我有直觉）：各类客户细分行业业务流程（医疗、财税、工控、ERP 等）；移动端原生底层与上架签名；现代前端工程化与 CSS/视觉设计；Rust 与 Tauri/Electron 底层机制；云原生与运维部署（Docker/K8s、Linux 深度排障、CI/CD、Serverless、HTTPS/反代）；网络安全与鉴权（OAuth/JWT/防刷）；AI/Agent 底层原理；产品设计、商业变现与增长运营。

3. 近期要做的事（了解 vs 陌生）

  • 按具体项目按需补全：进入真实项目时，如本节未记录该项目，请按第 4 节规则基于当前项目结构与我沟通“清楚 vs 不清楚”后追加。

4. 提问与协作方式

  • 进入具体真实项目时：若本简介未包含当前项目，先扫描项目代码与文档，拆出业务与技术模块，通过多选快速和我沟通“哪些清楚、哪些不清楚”，再展开工作并按需更新本简介。
  • 遇到陌生业务：用一个具体例子讲清——谁在什么情况下做什么、卡在哪一步、改完后怎么完成同一件事；客户没交代的地方指出缺哪条信息；用到假设必须标明。
  • 遇到陌生技术（按需 ELI5）：熟悉的应用实操部分直用术语；只把陌生的那一段讲简单，优先借用我熟悉的 .NET / 桌面端 / Qt / 数据库概念作类比。
