面向 AI 的个人简介

用途：仅供 AI 协作校准上下文（非求职简历），与全局沟通规范配合使用。最后更新：2026-11

1. 身份与场景

  • 角色：外包开发者 + 独立开发者。外包侧常接既有项目落实客户改动；独立开发侧做过桌面软件、移动 App、Web 网站/小工具及 CLI/浏览器插件。
  • 常见卡点：
    • 外包场景：陌生业务（代码能写，但没理解谁用、卡在哪、为什么改）与陌生技术栈底层。
    • 独立开发场景：功能能借助 AI 跑通，但常卡在选题验证、产品/交互打磨、打包签名上架与运维排障、安全/鉴权/支付接入、以及冷启动推广与变现。

2. 能力边界

  • 最熟的应用实操区（类比锚点，偏应用实操而非深钻运行时/内核底层）：WinForms / WPF（MVVM、绑定、界面与消息循环）、ASP.NET / ASP.NET Core Web API、EF Core / Dapper / SQL Server & MySQL 查询与事务、Qt 桌面端（信号槽、事件循环、QThread）、网络/串口/自定义二进制协议通讯、C++ 与 C# 互操作（DLL / C++/CLI / P/Invoke）。
  • 接触过 / 借助 AI 跑通过但不熟底层：
    • 传统 C/C++（原始指针、内存管理、结构体与位操作）、.NET/C++ 异步与多线程、Vue 前端联调；
    • 独立开发全链路实操（多借助 AI 跑通）：iOS/SwiftUI、Java/Android、Rust、Tauri/Electron、Chrome 插件（Manifest V3）、Python/Shell/PowerShell/Node 脚本与 CLI、GitHub Pages/Vercel/Cloudflare Pages 托管、基础域名/HTTPS/VPS/Serverless、大模型 API 与第三方 SDK 接入、开源与商店发布流程。
  • 明确不懂（盲区，不要假设我有直觉）：各类客户细分行业业务流程（医疗、财税、工控、ERP 等）；移动端原生底层与证书签名审核机制；现代前端工程化与 CSS/视觉设计；Rust 与 Tauri/Electron 底层机制；云原生与运维深度排障（Docker/K8s、Linux、CI/CD、反向代理）；安全与鉴权体系（OAuth/JWT/防刷/支付合规）；AI/Agent 底层原理；产品规划、交互设计与冷启动增长变现。

3. 近期要做的事（了解 vs 陌生）

  • 按具体项目按需补全：进入真实项目时，如本节未记录该项目，请按第 4 节规则基于当前项目结构与我沟通“清楚 vs 不清楚”后追加。

4. 提问与协作方式

  • 进入具体真实项目时：若本简介未包含当前项目，先扫描项目代码与文档，拆出业务与技术模块，通过多选快速和我沟通“哪些清楚、哪些不清楚”，再展开工作并按需更新本简介。
  • 遇到陌生业务：用一个具体例子讲清——谁在什么情况下做什么、卡在哪一步、改完后怎么完成同一件事；客户没交代的地方指出缺哪条信息；用到假设必须标明。
  • 遇到陌生技术（按需 ELI5）：熟悉的应用实操部分直用术语；只把陌生的那一段讲简单，优先借用我熟悉的 .NET / 桌面端 / Qt / 数据库概念作类比。
  • 独立开发协作：涉及选题、交互、打包上架、鉴权/支付或推广变现时，默认我缺底层直觉——先给具体取舍建议和避坑清单，不要只抛抽象术语。
